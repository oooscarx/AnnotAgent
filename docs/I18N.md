# Interface languages

The Web workspace supports English and Simplified Chinese. Use **Language / 语言** in the page
header. A saved choice takes precedence over the primary browser language; Chinese browser locales
use Simplified Chinese by default, and other locales fall back to English.

The choice is saved as `annotagent.locale` in this browser's local storage, survives reloads and
browser restarts, and synchronizes between same-origin tabs. Switching language re-renders the
existing component tree without remounting the workspace or discarding an unsaved form. If browser
storage is unavailable, switching still works for the current page session.

中文用户：在页面顶部的 **Language / 语言** 中选择 **简体中文**。以后使用同一浏览器访问该地址时，
会恢复此选择。该设置只改变界面显示，不会改变模型调用、标签定义或已保存的工作流。

## Translation boundaries

- Navigation, common actions, Project setup, Automation editing, sample tests, model and Provider
  settings, Plugin setup, Run/Review/Export controls, and lifecycle management use the shared catalog.
- UI status labels, known server guidance, accessible labels, dates, and key count messages are
  localized at presentation time. Raw status values, routes, form option values, stable IDs and API
  contracts remain unchanged.
- User-authored Project/Label/model names, prompts, model responses, evidence, JSON, provider errors,
  and external plugin descriptions keep their original text. Changing the interface language does
  not ask an LLM to translate anything or incur model charges.
- Untranslated messages, including some advanced technical help and server diagnostics, fall back
  to their English source text. This is not exhaustive Chinese coverage for every backend
  diagnostic or external Skill resource. CLI/TUI language is unchanged.

## Adding translations

`web/src/i18n.ts` provides locale resolution, same-origin persistence notifications, `useLocale`,
`t`, `translate`, and locale-aware number/date formatting. `App` subscribes to locale changes;
components call `t` during rendering, not while declaring module-level constants. The language
selector also subscribes so it is independently reusable.

English UI source messages are keys in `web/src/locales/zh-CN.ts`. Add a Chinese entry and wrap the
UI literal in `t("English source")`. For data-driven labels, translate only trusted presentation
labels at the rendering site. Never translate IDs, CSS classes, React keys, form values, prompts,
or strings used to build a request. Do not translate DOM nodes after React renders them.

For counts and names use whole-message placeholders, for example
`t("{count} items selected", { count })`. Keep placeholder names identical in both languages and
provide explicit singular English messages where necessary. Interpolated values remain verbatim;
React continues to escape text. To add another language, extend `Locale`, locale resolution,
the selector, and catalog lookup with its corresponding dictionary.
