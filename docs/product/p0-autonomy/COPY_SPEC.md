# P0 当前任务文案

默认区域只显示当前需要用户理解或决定的内容。Schema、Draft、revision、hash、
source request 和 Run ID 放在“技术详情”里。

## 1. 缺信息

标题：`还缺一个选择`

问题：`你希望给图片分类，还是框出其中的物体？`

已知信息：`已收到 6 张图片；训练用途是 YOLO。`

规则：一次只问一个会改变任务含义的问题。完整信息已经给出时不进入此状态。

## 2. 可以开始

标题：`先检查 3 张样例`

摘要：

> 从本次上传的 6 张图片中固定选择 3 张，查找 cup 和 bottle，边界包含完整
> 可见物体。使用 {model_name}，图片发送到 {provider_destination}；最多
> {builder_limit} 次方案调用、{sample_limit} 次样例调用。{cost_state}，不启动其余图片。

主按钮：`开始标注样例`

展开项：`查看图片、模型和预算范围`

规则：这一次批准覆盖同一未过期范围内的规范草稿、能力选择、Builder、静态
校验和 Sample。范围、图片哈希、模型接收方或预算变化时重新批准。

## 3. 执行中

按服务端事实选择一行：

- `正在检查图片 2/3`
- `正在生成标注方法`
- `正在校验标注方法`
- `正在测试样例 2/3`
- `样例已处理 3/3，正在整理结果`

辅助信息：`已用 38 秒 · 停止`

展开项：`查看步骤、Token 和费用`

规则：数字来自服务端持久状态。没有可计算总量时只显示阶段，不显示估算百分比。
刷新、重新打开或 GET 不负责推进任务。

## 4. 需要审核

标题：`这张图需要你判断`

问题：`这张图有一个边界需要确认，已在右侧定位。`

针对边界的补充：`请确认杯身和把手都在框内，并排除桌面阴影。`

主动作：`保存这张图的审核`

其他动作：`没有 cup 或 bottle`、`排除这张图`

规则：先定位图片和候选，再提具体问题。合法空结果仍需用户确认整图，不自动
写入负样本。保存样例修正不等于接受正式标注或批准全量。

## 5. 已交付

标题：`训练数据包已生成`

摘要：`6 张图片 · 2 个类别 · YOLO Detection`

主动作：`下载 ZIP`

次要入口：`查看结构检查和审核记录`

规则：只有服务端 Package 为 Ready 且 ZIP 可读取时显示。结构检查通过不能写成
“标注准确”或“训练完成”。

## 外部阻塞与失败

| 服务端事实 | 默认文案 | 安全动作 |
| --- | --- | --- |
| 缺少可用模型 | `缺少可用于图像定位的模型。` | `选择模型`，保存后重新核验原 Task |
| Provider 明确未接收 | `模型服务没有接收这次请求。` | 在原预算和幂等规则内提供重试 |
| 远端结果未知 | `请求已经发出，但没有收到可确认的结果。` | 显示调用记录；不自动重发 |
| 返回结构非法 | `模型返回的结果无法安全用于标注。` | 保留原响应证据，按有限修正规则处理 |
| 合法空结果 | `这张图没有检测候选，请确认是否确实没有目标。` | 进入整图判断 |
| 有候选但坐标投影失败 | `候选位置无法可靠映射到原图。` | 显示原图和错误类型，不放松 Geometry Gate |
| 预算不足或授权过期 | `当前预算或授权已结束，任务停在这里。` | 展示已完成结果和新的差额范围 |

失败文案不得统一改成“请人工标注”，也不得自动切换到预置候选。

## 默认流程中删除的文字

- `准备 Schema`
- `采用 proposal`
- `保存 Draft`
- `选择 source_run_id`
- `读取回执`
- `启动 Sample`
- `编辑此样例的 Workflow 草稿`
- `确认目标并准备方案`
- `生成方案并测试样例`

对应技术状态可以出现在展开后的轨迹中，不作为普通用户的下一步指令。

## Paper & Graphite 呈现

- 中间会话保留普通消息和一个当前操作块。
- 操作块最多约四行摘要、一个主按钮和一个 Chevron 详情。
- 右侧沿用现有结果画布和图片队列；左侧不再放第二套预览。
- 执行、失败和审核状态使用现有 token、细边框和普通文字，不增加彩色大卡片。
- 全量处理只在用户判断三张样例后出现；打包只在正式审核阶段出现。
